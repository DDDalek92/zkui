# D01-C：合法旧历史 NULL 字段的页面回归

2026-10-15；基线 `d34c3ddbc8537438b22b28e88b60c4f77e7367f0`（Fork #29）。
这是旧数据展示兼容修复，不是H2/Flyway驱动升级或完整历史库迁移放行。

## 复现与修复

原始、未改写的V1允许每个非ID列为NULL。`HistoryStorageIT`及隔离迁移预演已能读取/保留它们，但历史页模板直接插值日期、对NULL文本执行`?html`，未覆盖页面渲染。

新增`NullableHistoryIT`在测试自行创建的临时H2中，经独立JDBC插入全NULL行、空串行及含HTML/中文/emoji的行；非连续ID包含大于2^53的Long。真实组装JAR在`/legacy/`前缀下登录并读取历史页。修改前两个用例中一项失败、一项通过：ADMIN页面触发`InvalidReferenceException`（`history.changeDate`），HTTP仍为200，但表格被中断，较后的历史行缺失；USER拒绝访问正常。不能把200当作渲染或迁移成功。

修复只改变模板：NULL日期/文本显示为空，文本仍先取空串默认值再做HTML转义；ID用`?c`保留精确整数字符，不使用本地化分组格式。不删/补写历史、不把NULL改成空串入库，不动V1、Flyway记录、DAO迁移或认证/CSRF策略。

回归要求全NULL行四个空单元格，空串与HTML历史都完整显示，危险标签转义，两个大ID逐字符准确，重复HTTP读取仍保留历史，日志没有`InvalidReferenceException`；USER返回403且不含历史摘要或ID。所有服务/数据库/凭据/数据均为测试自建，未访问生产或用户旧库。
