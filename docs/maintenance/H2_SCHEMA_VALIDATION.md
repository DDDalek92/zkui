## 审查发现与实现

已有五项预演比较历史行、Flyway 元数据、生成 ID 和重开，但未比较历史表的结构/索引，也未执行约束负向检查。数据相同不代表 DDL 相同。

`H2MigrationProbe` 现在在原引擎生成、LEGACY 导入/重开、旧副本恢复、Flyway4 桥接后、现代导入及两次 Flyway13 migrate/validate 后检查：

- 五列的名称/顺序、JDBC BIGINT/VARCHAR/TIMESTAMP 类型；三个 VARCHAR 长度为100/500/500；ID 非空且自增，其余四列可空。
- 有序主键仅 ID；实际索引按列序/升降序、唯一性和过滤条件比较，不依赖自动生成名称或物理索引实现。
- 重复 ID 必须以 SQLState23505 拒绝；用户101、摘要501、IP501个ASCII字符分别以22001拒绝。精确100/500/500边界和四个非ID列全NULL插入必须成功。
- 探测写入均使用显式低位测试 ID、事务回滚；前后再次精确比较全部历史行与 Flyway 表记录；原有大ID继续生成/重开测试仍执行。

结构既与固定 V1 语义比较，也与旧引擎捕获结果比较。旧1.3.174和候选2.5.252对 BIGINT COLUMN_SIZE 的19/64、TIMESTAMP DECIMAL_DIGITS 的10/3报告不同；不把这些驱动字段原样当作跨版本精度等价结论。现有时间值仍逐字段按 Instant 比较，不因此声称任意精度时间戳兼容。无索引谓词在旧驱动为空串、新驱动为NULL，归一为“无”；非空谓词仍参加比较。

新增第六项预演只将一次性候选库的摘要宽度扩大至501。先确认历史行/Flyway记录完全不变，再确认结构验收确实拒绝该目标；原始导出字节及封存库文件名/SHA256不变，旧驱动恢复副本仍成功。没有改写 V1、原导出、封存库或已应用迁移记录。
