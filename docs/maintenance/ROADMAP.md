## 阶段 M1：建立测试和 CI

- 修正测试占位现状，建立 JUnit 单元测试及 ZooKeeper 隔离集成测试。
- 建立 GitHub Actions CI，记录基线失败；保存构建/安全/测试报告。

## 阶段 M2：处理先发安全风险（可与 M1 并行）

- 优先隔离验证并修复 SEC-01（导入接口的角色授权）与 SEC-02（匿名 REST/敏感配置）。
- 随后进行 CSRF、会话固定、导入 URL/上传边界、敏感日志、代理信任安全检查。
- 安全修复每个独立 PR，强制包含回归测试和发布说明。

## 阶段 M3：整合社区 PR

1. 低风险：#87、#109 等能独立验证的小改动。
2. 功能类：#54、#110、#88、#86，先处理回归和外部资源约束。
3. 权限类：#50、#107，先确认认证/权限架构后实现，不直接引用未审查旧代码。

5. 复查历史已关闭但未合并 PR 的残留价值，避免重复引入已合并代码。

每项必须注明上游作者、原 PR 链接、处理理由、新 Fork PR 和验证结果。

## 工作协议

每项用 `maintenance/<topic>` 或 `fix/<topic>` 分支单独提交 → CI → 审阅 → 合并到受保护的 `master`。绝不直接批量关闭原作者仓库 Issue；对作者贡献保留来源。动态测试未完成的结论标记“待验证”。
