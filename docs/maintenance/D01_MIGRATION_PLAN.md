## Java17 插桩候选审查

现状为 ActiveJDBC 1.4.8、instrumentation 1.4.1，构建插桩绑定 process-classes。
[JavaLite 官方插桩说明](https://javalite.io/instrumentation)要求编译后执行插桩；
只用 IDE 编译或跳过插件不能证明模型可运行。
[官方发布说明](https://javalite.io/releases)列出 3.5-j11（2024-07-30，Java11 基线）；
可作为 ORM 与插件同版本升级的**候选**，不是本项目已验证的 Java17 结论，也不能继续宣称兼容 Java8。

下一次有构建环境时，先保存旧基线 Java17 的实际失败日志，再验证候选：
模型发现/静态查询、set/get 类型和日期、生成主键、LIKE 参数绑定、已关闭连接后的结果使用、
失败后的线程连接释放、组装包中的模型注册资源与 SLF4J 绑定。
若改用其他持久层，也必须覆盖同一组行为，而不是单纯删除插桩步骤。
CI 与容器的 JDK 要随最低运行要求同步；不能让 Java11 字节码进入仍标 Java8 的运行镜像。
只改 pom 版本号或增加 --add-opens 不作为验收。

## 合成副本夹具与隔离约束

未来测试夹具全部由测试自行生成，不导入用户数据库或凭据。
固定记录：空库，以及含中文、emoji、换行、首尾空格、单引号、反斜杠、
空字符串/NULL、500字符摘要边界、确定日期和非连续大整数 ID 的历史库。
分别验证字段允许的 NULL；不要把任意二进制 ZK 数据当作 histories 的 schema 能力。
由旧驱动与实际旧 Flyway 生成版本元数据，保存实际字段/类型/行值快照，不臆定表结构。

| 路径角色 | 唯一用途 | 不变量 |
| --- | --- | --- |
| sealed-source | 已关闭的旧版本合成库与旧应用配置快照 | 后续驱动不得打开；前后全文件清单和 SHA256 相同 |
| old-work | sealed-source 的独立复制品 | 仅旧 H2 1.3.174 进程可开，导出前做只读逻辑快照 |
| export | 旧驱动生成的 SQL 与逻辑清单 | 权限收紧；不上传真实数据；保留原始导出，修订版另存并记录差异 |
| new-work | 全新、不存在的目标库路径 | 只由新驱动进程创建，拒绝源目标重叠/符号链接别名 |
| rollback-work | sealed-source 的另一份独立复制品 | 只供旧应用恢复演练；不是把新库交给旧驱动 |

新旧驱动不得放进同一 classpath，不能只靠同名 org.h2.Driver 的加载顺序。
不要复制正在写入的库；仅在测试进程关闭、锁释放并校验文件清单后复制。
源副本只读校验还应防止 JDBC URL 中 INIT/RUNSCRIPT/远程地址等附加行为；
未来工具只允许测试管理的本地路径，不接受任意用户 URL。
测试用 env=prod，不能通过 env=dev/Flyway.clean() 重建来掩盖迁移失败。

## H2 转换验收步骤（全部待执行）

1. 锁定旧/新应用 SHA、完整驱动/工具坐标及 SHA256、JDK、OS、时区、编码与夹具种子。
   用旧版本建立夹具，关闭后封存；确认 V1 字节未改，保存旧逻辑快照。
2. 旧驱动仅打开 old-work，导出 SQL；新驱动仅在 new-work 建库并导入。
   [H2 官方迁移说明](https://www.h2database.com/html/migration-to-v2.html)
   要求用原版本 SCRIPT 导出、新版本新建库后 RUNSCRIPT；
   FROM_1X 是否需要以及对 **1.3.174** 的实际适用性必须测试，
   不把针对其他 1.x 版本的说明当作本项目成功证据。
3. 对比 histories 按 ID 排序的每个字段；字符串精确比较而非 trim，
   NULL 与空串区分；日期按声明时区/实际精度比较，不能只比较格式化显示。
   比较所有 ID、行数、最大 ID、主键/列约束及相关索引。
   SQL 文件字节相等不是数据库逻辑等价的要求，不能以只比较 COUNT(*) 替代逐字段校验。
4. 枚举并逐字段比较实际 Flyway 旧版本元数据；若新 Flyway 需转换元数据，
   在目标库中由选定版本的受支持路径完成，明确每项映射、旧快照与新验证结果。
   不手工删除/改 checksum 或盲目 baseline/repair。
   没有证明兼容路径时停在副本，不启动应用对用户库做尝试。
5. 启动新应用两次（仅连接测试自建 loopback ZK），验证 ADMIN 历史页、查询过滤、
   原历史保留及新增一条记录的生成 ID 不冲突且大于既有最大值。
   从数据库重新读取确认实际保存，不依赖被吞掉异常的方法返回值。
   再验证 USER 无历史访问权限、连接均释放。
6. 核对 sealed-source 全文件 SHA256，使用旧应用/旧 JDK/旧驱动与 rollback-work
   恢复读取和新增；新应用/新库独立保留供诊断。
   这是“未切换前/无新业务写入”的可回退演练，不代表新版本写入后可无损降级。
   有新审计记录后的回退需单独保全/核对差量，禁止声称简单改回 URL 即无损。

## 必测失败与停止条件

| 失败注入 | 验收要求 |
| --- | --- |
| 截断 SQL、导入中断、磁盘满或不可写 | 不切换配置；标记目标不完整；不把半成品当已迁移；不改 sealed-source |
| 元数据 checksum 不匹配、未知 schema 或缺表 | 明确失败，不删除记录/clean/隐式新建覆盖 |
| 重复执行、已有目标库或源目标同路径 | 不覆盖，不重复插入；明确拒绝或已验证的幂等协议 |
| 新驱动误指旧路径、双进程锁竞争 | 在打开前拒绝危险路径；锁失败不得回退到别的空库继续 |
| 迁移后历史插入失败 | 非零退出/不可就绪或明确且已验收的降级策略；不能沿用当前“仅日志”当成功 |
| 恢复时原副本 hash 改变 | 停止演练，保留证据，不能继续宣称可回滚 |

以上是未来测试的预期结果，不是现有应用/工具已经实现的保护。
迁移 CI 必须上传不含真实数据/凭据的 manifest、断言结果和失败阶段；
记录准确 head SHA、job/run 链接和各平台计数。
现有 92 项 Java 回归成功只证明原维护基线，不替代本矩阵。
